인자: $ARGUMENTS

이 창은 **감독만** 한다. 구현·검사는 스크립트가 여는 새 `claude -p` 세션이 한다 (이 창에 대화가 쌓이지 않게).
돌고 있는지는 기억이 아니라 스크립트로 판단한다.

1. 먼저 `bash scripts/work-loop.sh <작업명> [서비스] --status` 를 실행한다.
   - `▶ 돌고 있음` 이면 새로 시작하지 않는다. 그 출력(pid · 시작 시각 · 최근 로그)을 요약하고, 2번처럼 Monitor 로 `--watch` 를 붙인다.
2. 아니면 `bash scripts/work-loop.sh $ARGUMENTS` 를 **백그라운드로** 실행한다 (Bash run_in_background). 출력을 다른 파일로 돌리지 않는다
   — 스크립트가 `.cache/workloop/autoloop/<작업>[-<서비스>].log` 에 스스로 남긴다.
   - exit 4 (커밋 안 된 변경이 있어 시작 안 함) 이면 그 목록을 보여주고, 커밋이나 stash 를 할지 사용자에게 묻는다. 대신 처리하지 않는다.
   - 바로 이어서 **Monitor** 로 `bash scripts/work-loop.sh <작업명> [서비스] --watch` 를 붙인다 (timeout_ms 1800000, 설명 "work-loop <작업> 진행").
     진행 줄(항목 번호 · 세션 시작/끝 · 비용 · 커밋 · 경고)이 이 창에 실시간으로 보인다. 줄마다 따로 해설하지 않는다 — 사용자가 직접 본다.
     Monitor 가 만료되고 루프가 아직 돌고 있으면(`--status` 가 `▶ 돌고 있음`) 같은 명령으로 **다시 붙인다**. 루프가 끝나면 --watch 는 스스로 끝난다.
3. 끝나면(백그라운드 완료 알림) 출력의 마지막 `■ 종료` 부터 끝까지만 읽고 요약한다:
   - 멈춘 이유 · 완료 수 변화 · 세션 수 · 비용 합계
   - 스크립트가 대신 한 커밋 · stash 로 보관한 변경 · push 결과
   - 남은 것 (사람 작업 · 보류 사유 · 선행 대기) 과 사람이 할 다음 행동
   - 계속할 수 있으면 다시 칠 명령 (`/work-loop …`)
4. 실패한 세션이 있으면 출력에 적힌 로그 경로만 알려 준다. 로그를 통째로 읽지 않는다.
5. 이 창에서는 코드를 고치거나 features.json 을 바꾸지 않는다.

멈춤은 스크립트가 보장한다: 구현 세션 최대 --max(기본 8) · 전체 세션 2×max+1 · 총 --hours(기본 3) · 세션당 40분 ·
진행 없는 세션 2회 연속. 비용 한도는 기본 없음(--budget 을 따로 주지 않는다). 이 창이 반복을 이어 붙이지 않는다 (끝나면 다시 시작하지 말고 보고만).
